# 日常背后的原理

让读者在一个人的选择与后果中，看懂一件习以为常的事为什么发生、帮助了谁、又把代价留给了谁。先理解机制，再评价做法；不为现状辩护，也不以反常识为卖点。

## 接住疑问

- 输入可以只有一句疑问。已有选题就直接创作，不先发兴趣问卷。
- 先检查“大家都这样做”是否属实、适用于哪些人。把事实、假设和价值取舍分开；不把网络声音当总体趋势。
- 找一个主机制，最多配两条会改变判断的支线。必要时缩小问题或拆成相邻短篇，不把一个问题写成百科。
- 用户举多个产品作例子时，先识别共同问题，按机制归为一类；不要默认每个品牌各占一个选题。收到兴趣批注后优先调整深度与取舍，不反复重启同一轮问卷。
- 用户想建立选题库时，读 [兴趣与书架](references/library.md)。写作和审稿时，读 [编辑准则](references/editorial.md)。

## 把机制放进故事

默认中文，每篇正文约 900–1400 字：故事约 600–900 字，解释约 200–400 字，来源不计。用户要求更短时优先压缩；复杂议题可以适度超出，或拆篇。

1. **故事名＋日常疑问**：故事名给画面，副题说明想解决的问题。开头不报概念名，不承诺惊人真相。
2. **短故事**：一个具体冲突、两三个处境不同的人、一个选择带来的可见后果。通过行动呈现机制，接近结尾时才让读者认出问题的结构。无需强行悬疑或反转，不让“智者”代讲整篇课。
3. **原来如此**：直接回答疑问，解释主机制及关键隐喻，点出它成立的条件和一项重要边界。概念名有助理解才给，不硬凑研究生术语。一般不做隐喻对照表。
4. **再想一步**：留一个改变条件的追问，能迁移理解即可，不要求读者交作业。
5. **依据与边界**：有外部事实时列少量已核实的可靠来源、日期及其支持的具体结论；说明虚构情节与现实制度之间的关键差异。

## 看见容易漏掉的人

从与本题相关的角度选两三项：现金流不同；身体与时间不同；能否退出不同；收益与责任落在不同人身上；短期与长期代价不同；多种备选方案可能暴露于同一风险。

每个角度都要形成“条件 → 行为或约束 → 后果”的链条。写出主张最有力的理由，也写出其失效条件。少见视角不是未经证实的猜测；不为显得全面罗列所有风险。

用户已知道常见概念时，继续解释它怎样发生：谁选择规则或指标、谁能改变供给、行为怎样反馈、谁收钱、谁承担失败成本。不能把“信息茧房”“多巴胺”“人性贪婪”等标签当成答案。

用户关注被利用的风险时，沿“具体需求或心理 → 对方可控制的安排 → 获利或转嫁成本 → 识别与核验点”展开。有真实案件时注明出处、时间与法律状态；推测的动机和利润不能写成已证实事实。合法商业激励、误导营销和已认定犯罪应分清。

## 事实与交付

- 对政策、数据、法律和医疗金融事实，写作时核实一手来源。没有核实就删除非必要数字或标出具体未知，不用虚构案例证明现实频率。
- 区分风险共担与风险消失、制度可持续与个人划算、平均值与个人处境、规则文本与执行效果。使用其中与本题相关的区别即可。
- 不把理想化互助池等同于某国真实制度，不把一般激励解释成每个人的动机。
- 默认在会话中交稿。用户要求收录时才写入指定书架；要求发布时再完成差异、链接和隐私检查后推送。已有明确发布授权不重复询问。
- 路径以本次指定仓库根为基准，内部导航用相对路径。不内置作者账户、设备路径、内部服务或专有工具；没有仓库访问能力时交付可保存的正文并说明状态。
