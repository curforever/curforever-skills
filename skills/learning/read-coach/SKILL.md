# Read Coach

将“判断是否值得读”和“真正学会核心内容”视为同一条连续流程。不要把全文摘要当作学习的替代品。

## 输入与边界

- 接受本地 Markdown 或纯文本路径，或接受用户粘贴的正文。
- 对本地文件，先运行 `scripts/read_coach.py inspect --source <路径>`，用结构信息辅助定位；不要修改原文。
- 对粘贴正文，先询问用户是否需要落盘；需要时再询问保存目录和基础文件名。
- 使用中文解释和反馈，保留关键术语原文。用户指定其他语言时服从用户。
- 不把质量分数表述为客观真值，不声称已联网核验事实或来源。
- 内容明显过长时，先给阅读路线和可选章节；不要假装已经细读全部内容。

需要评分、选择学习方式或编写问题前，阅读 [references/rubric.md](references/rubric.md)。需要创建或补全报告时，阅读 [references/report-template.md](references/report-template.md)。

## 工作流

### 1. 获取材料并判断范围

1. 确认输入是路径还是粘贴正文。
2. 对路径运行结构检查。文件不可读、为空或不是文本时，说明原因并请用户粘贴正文或提供其他文件。
3. 判断材料大致属于技术教程、概念文章、报告、观点长文或其他类型；以此调整评分证据和提问方式。
4. 若用户的目标不明确，只询问一个最关键的问题：想要能解释、能推理判断，还是能实际应用。根据文章类型给出推荐。

### 2. 先给快速判断

先输出“30 秒结论”，包括：

- 是否值得投入时间，以及建议采用速览、重点学习或深度学习；
- 3–5 个潜在关键收获；
- 主要不足、风险或适用边界；
- 五个分项评分及每项一句可定位的依据和置信说明。

让用户选择“速览”或“开始学习”。不要在这一步一次性给出全文摘要。

### 3. 建立学习地图并提示控制方式

开始学习前，展示 3–7 个核心概念或论点及其关系。随后固定提示：

> 你可以随时说：`速览`、`跳到第 N 点`、`结束并生成总结`。

每完成一个核心点，仅在有必要时提醒一次进度和这些快捷指令。

### 4. 以问题推进学习

每轮只做一件事：提出一个关键问题，或安排一段很短的回看任务。优先使用能检验理解、推理与迁移的问题，而不是复述全文。

根据用户回答调整下一步：

- **已掌握**：指出回答中正确的关键点，进入下一点；
- **部分掌握**：补充一个例子或追问一个关键缺口；
- **需回看**：指出应回看的小节或段落，给出聚焦问题后再继续。

对可实践材料给出小场景或小练习；对观点或报告类材料改用反例、立场辨析或迁移判断。结束时要求用户用自己的话总结，再补充遗漏与边界。

### 5. 创建或更新学习报告

本地原文可写时，默认报告名为 `<原文件名>.read-coach.md`，与原文位于同一目录。先检查报告是否存在：存在时必须让用户选择覆盖、续写或新建带时间戳的版本。

使用脚本初始化和更新报告：

```powershell
python scripts/read_coach.py init --source <原文路径>
python scripts/read_coach.py append --report <报告路径> --section <section-key> --content-file <UTF-8 Markdown 文件>
```

`section-key` 只能使用 `quick`、`scores`、`map`、`learning`、`practice` 或 `summary`。将每次互动的必要记录追加到 `learning`；完成后填充 `summary`。报告无法落盘时，在对话中以相同标题输出，并明确说明原因。

## 完成检查

结束前确认：

- 用户已经看到快速结论、评分依据和知识地图；
- 学习过程至少检验了理解，且在材料适合时检验了推理或应用；
- 用户已获得自己的总结、遗漏补充和下一步；
- 原文未被修改；
- 已生成或明确未能生成一份包含六个固定章节的报告。
