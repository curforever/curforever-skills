# 项目知识格式

本文件只在新建或修订项目知识时读取。默认根目录是当前项目 `knowledge/`；用户明确指定项目内其他目录时遵从指定。

## 归类与查重

先在 `INDEX.md` 和知识目录搜索主题、同义词、产品名或规则条件。旧条目适合承载新证据时原位修订，不为同一结论新建副本。旧目录和格式不迁移。新条目按主要用途选择一个子目录：

| 子目录 | 放什么 |
| --- | --- |
| `concepts/` | 术语定义、关系和通俗解释 |
| `facts/` | 有来源的事实、指标与口径 |
| `rules/` | 条件与行动、可检验预期、实际结果 |
| `procedures/` | 可复用操作步骤与检查点 |
| `decisions/` | 用户或团队已确认决策及有效范围 |
| `cases/` | 可复用的任务情境、行动和已观察结果 |

首次出现某类别才建目录。一个主题跨类别时选主要用途并用索引或相对链接关联，不复制全文。

## 条目最低内容

写明标题、简短结论、知识类型、适用范围/条件、来源或观察依据、状态、记录或最后复核日期、复核触发，以及修订记录。来源优先具体文件、可点击的直接网页或明确的用户确认；模型回忆和自述不能单独当证据。事实和推断分开。可能状态：已验证、用户确认、阶段性、待验证、存在冲突、已废弃。用户确认只证明用户的选择或口径，不自动证明外部事实。

可观察的 `rules/` 增加预期结果、实际结果、反例。未观察到结果时写“待观察”；多个假设都符合已有观察时并列保留，并写明可区分它们的新证据。不要捏造概率，不从一次成功推到普遍有效。

修订记录用短句写 `YYYY-MM-DD：依据……，将……修订为……；原结论……`。更正或废弃时保留足以理解来龙去脉的旧说法及证据，不整段复制历史聊天。没有 Git 的项目尤其需要这条记录。

## 索引与回读

沿用现有 `INDEX.md` 表头和链接风格；新项目可用“主题 / 资料 / 来源 / 日期 / 状态 / 最后复核 / 复核触发”。索引条目写面向检索的主题词，链接到实际文件。更新后回读条目及索引，确认路径可达、状态一致、没有重复主题。涉及敏感数据时只保留抽象结论与适合保存在本项目的来源描述。
