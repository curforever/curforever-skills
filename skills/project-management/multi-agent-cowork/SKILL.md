# Multi Agent Cowork

让支持本地文件和工具的不同 AI 在同一项目接力。角色属于本次工作，不绑定产品、模型或会话。规划者可以接手执行，解决阻塞后再交回。第一版通过共享文件协作，不启动其他 AI、不发送消息、不配置 MCP。

## 从用户意图进入

用户不用记模式。结合当前请求、已确认任务、既有授权和真实状态选择：

| 用户意图 | 内部流程 |
|---|---|
| 规划需求、拆分任务、准备交给其他 AI | plan |
| 开始做、继续明确的任务 | execute |
| 检查实际结果、验收 | review |
| 看进度、只调用本 Skill 且没有明确可延续行动 | status |
| 给我发给另一个 Agent 的完整提示词 | handoff |
| 原执行者做不下去、让我/规划者先修好再交回 | execute，目的 repair，必要时先恢复旧执行轮次 |

只有任务或意图确实不明确时才问一个必要问题。不要因磁盘上存在计划就自动执行。用户已授权的明确任务可以继续；换角色本身不要求重新审批。交接提示词只是文本产物，不自动转交、不取得执行权。

## 定位任务与最小上下文

顺序：用户给定任务记录绝对路径 → 当前会话已确认的任务 → 唯一匹配需求与工作区的候选。存在多个候选时展示名称和状态供选择，不猜“最新任务”。原生会话 ID 取得不到就留空，不伪造。

先用下方辅助脚本 list/show 读取状态；再读目标项目 AGENTS.md、README.md、PROGRESS.md、DECISIONS.md 和知识索引中与任务有关的条目。它们缺失不强制初始化整个项目。任务记录、计划和真实源码互相核对，不把对话总结当唯一事实。原 project-close/resume 不需要加载或修改。

## 按需读取

- 实际规划、执行、审查、handoff 或接管：读 [workflow.md](references/workflow.md) 对应段落。
- 操作状态、任务版本、工作区锁，或处理中断：读 [protocol.md](references/protocol.md)。
- 新任务正文用 [task.md](templates/task.md)；回执、审查、提示词模板按对应流程使用，不一次性全部加载。

## 辅助脚本

运行本 Skill 目录下 scripts/cowork.py（Python 3，Windows/POSIX 本地文件锁；不调用模型）。先看 --help，子命令也有 --help。从本 SKILL.md 路径解析脚本绝对路径，命令参数按 shell 规则引用，避免依赖调用者 cwd。

只读 list/show/handoff 不创建记录。写操作要求明确的项目根目录；task 可以是精确记录目录或 ID。show 给出 version 和 evidence，写操作按文档带上预期版本。claim 返回 run 和 token；token 仅供当前执行轮次使用，不复制进交接提示词。

## 必要约束

- 在原目标、文件范围、依赖限制和验收内自主调整步骤，回执说明理由；扩大任务需要收敛授权，不能静默改写计划。
- 同一工作区串行写入；咨询锁只约束遵守协议的调用方，不构成沙箱。保留现有改动，不自动提交、推送、回滚或修改 Git 忽略规则。
- 接手前确保原执行已暂停或实际停止。超时、无输出、短命辅助脚本退出都不能证明旧 AI 已停止。原任务/计划/历史保留，每次换执行者创建新 run。
- 执行完成保存证据并等待审查；只读交付或用户明确省略审查可直接完成。同一执行者的自查如实标明，不能称独立审查。
- 没运行的检查标为未运行；状态使用已完成步骤和具体阻塞，不编造百分比。不高频查询、不反复加载整段日志。
- 第一版共享本地文件系统；其他机器/云端需要显式传递记录和路径映射。缺少工具时报告缺口。

输出保持简短：当前 feature/任务、已做工作及证据、阻塞、下一步。handoff 请求则给出完整可复制提示词。
