# Skill 发布管理设计

日期：2026-08-23  
状态：已获用户批准，待实施

## 目标

将 `skills/` 中尚未发布的个人 Skill 以与 `curforever/curforever-skills` 一致的目录结构发布到 GitHub，同时保留本地原始 Skill 不变。新增 `skill-manager`，使后续更新可以重复执行相同的整理、脱敏、校验和推送流程。

## 边界

- 源目录：当前目录下除 `__MACOSX` 外的 Skill。
- 目标：`https://github.com/curforever/curforever-skills` 的 `main` 分支。
- 不修改既有源 Skill；所有改写在临时发布副本中发生。
- 发布文件不得包含本机绝对路径、用户目录、令牌、密码、电子邮箱或其他可识别个人的信息。
- 本机路径以仓库内相对路径替代。

## 结构与数据流

`skill-manager` 的同步脚本接收源目录和目标仓库地址。脚本先将目标仓库克隆到临时目录，再将尚未发布或已更新的源 Skill 复制到相应主题目录。复制后对文本文件执行路径规范化和敏感信息扫描；任何未能自动安全处理的匹配都会使脚本停止且不推送。通过结构校验后，脚本显示变更摘要，并在允许推送时创建 Git 提交、推送到 `main`。

## 目录规范

- 主题目录：如 `communication/`、`learning/`、`productivity/`、`development/`、`project-management/`、`writing/`。
- Skill 目录必须含 `SKILL.md`；可选目录为 `agents/`、`references/`、`scripts/` 和 `tests/`。
- 忽略 macOS 元数据目录、缓存、编译产物和私密配置。
- 远端既有 Skill 不覆盖，除非源版本经明确映射为同一 Skill 且内容确有更新。

## 安全与失败处理

- 仅在临时副本中改写绝对路径；源文件始终只读。
- 使用允许列表识别安全的项目相对路径；对于疑似密钥、令牌、邮箱或用户主目录的内容，以失败终止替代自动发布。
- 推送前检查工作区差异、Git 身份与远端可访问性；认证或冲突失败时保留临时副本路径和可恢复说明。

## 验证

每次同步至少验证：所有发布 Skill 含 `SKILL.md`；禁止文件未进入目标树；文本中不存在本机绝对路径或敏感模式；脚本的预演模式不产生 Git 写入；提交前后的 Git 状态与远端分支一致。

## 使用接口

日常使用者在本地更新某个源 Skill 后，调用 `skill-manager` 并要求“预演同步”或“同步并推送”。默认先预演；只有明确请求推送时才执行网络写入。
