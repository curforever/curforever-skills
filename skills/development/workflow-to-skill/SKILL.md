# 工作流提炼

把多次任务中稳定、有价值的做法压缩成可复用 skill。提取触发条件、判断规则和输出契约，不把历史聊天记录直接搬进技能说明。

## 按请求选择产出

- 用户要求“发现重复工作”“看看哪些值得做成 skill”：读取相关记录，交付有依据的候选；暂不写入技能目录。
- 用户要求“自动整理成 skill”“把这些流程做成 skill”：在指定目录创建证据充分的新 skill；证据不足的项目留作候选，不为满足数量而编造流程。
- 用户要求优化现有 skill：对照历史反馈修正相关规则，保留原有功能和无关配置。

请求已授权创建时，先说明选择依据与目标目录，再继续写入，不反复要求批准。目录未指定时优先采用会话已约定的 skills 目录；没有约定则采用当前环境的用户 skills 目录。改写已有 skill 必须有更新授权；否则提出合并建议。

## 1. 确定实际可用的记录

列明本轮的来源与覆盖范围，例如当前会话、用户指定的历史任务、项目交接文档、操作日志或用户提供的记忆摘要。

- 只能分析本轮真实可见或通过可用工具读取的内容。提供了工具时先查找适合的历史读取能力，按范围读取；没有工具或访问权限时，明确说明限制。
- 不声称可读取所有历史、隐藏记忆、已删除任务或完整操作轨迹；也不能把当前对话当作用户全部日常工作。
- 从索引、任务摘要或项目进度记录开始，再按候选流程读取必要片段。避免为寻找习惯而扫描整个磁盘、所有项目或无关个人资料。
- 遵守来源的访问范围和项目规则；需要敏感记录且尚无读取授权时，先请求该具体范围，继续分析已获授权的资料。
- 没有可用历史时，可以分析用户提供的一两个真实案例或明确描述的 SOP。仅凭一个案例形成的是暂定候选，不能标为已发现的高频习惯。

本轮是一次有范围的分析，不创建持续监控、定时任务或长期行为档案。

## 2. 发现重复的工作流

按任务目的聚类，而不是按关键词聚类。寻找以下信号：

- 不同任务中反复出现的输入、步骤顺序、判断节点和固定交付物。
- 用户多次纠正的输出形式、范围边界或验收口径。
- 每次都要重复说明的上下文、工具操作或失败处理方式。
- 能减少重复解释、返工或机械劳动的稳定流程。

通常优先考虑至少两次独立任务中出现的模式；同一任务的多条日志、重试和引用不算多次独立发生。用户明确说这是日常流程时，记录为“用户确认的习惯”，与“从记录观察到的重复”区分。

区分通用规则、项目限定规则和一次性例外。最近一次明确指令优先于已被用户纠正的旧做法；无法确定的冲突列为待确认，不把旧错误固化。

## 3. 筛选值得创建的技能

先查看已有 skill 的名称和描述，仅对最相关的技能读取正文，判断新增、合并还是局部更新。

候选需具备：清楚的触发场景、可重用的方法、可观察的产出，以及足够支持关键规则的来源。优先推荐使用较频繁、返工代价较大、流程稳定且没有被现有 skill 覆盖的项目。

以下情况通常不单独创建 skill：仅需一句通用偏好、只有某次任务的事实总结、已经由现有 skill 完整覆盖、只需固定脚本即可完成的机械操作。分别建议放入合适的偏好配置、项目知识、现有 skill 或脚本。

在报告候选时读取 [references/candidate-template.md](references/candidate-template.md)。给出少量优先项和证据，不承诺发现固定数量的技能，也不凭感觉捏造使用频率或节省时间。

## 4. 抽象成可复用能力

对已选择的工作流，提取以下内容：

- **触发与边界**：什么时候使用，哪些相似请求不适用。
- **输入与参数**：目标、数据来源、输出位置，以及每次会变化的值。
- **步骤与判断**：关键顺序、分支条件、质量标准、停止条件。
- **输出与验收**：用户实际需要的交付物和检查方式。
- **经验与例外**：已验证的纠错规则，以及何时不能照常执行。

只保留能改变执行质量的经验，不复制完整对话、真实日报、个人档案或凭据。将真实人名、账号、内部项目标识和本地绝对路径转为中性描述或参数；项目路径采用相对路径或运行时输入。

把个人偏好标为可配置默认值，不把某次偏好写成所有用户的强制规则。若确实依赖私人项目结构，明确限定适用范围，或将本地参数放在不随公开版本发布的配置中。

不因历史上执行过提交、推送、交易、发消息或删除，就赋予新 skill 对这些动作的永久授权。将分析步骤与实际执行动作的授权分开。

## 5. 创建与校验

创建或更新时，使用可用的 `skill-creator` 规范和校验工具；若环境没有该 skill，按以下最小规范完成，不依赖不存在的工具：

- 目录名与 frontmatter 的 `name` 一致，采用小写字母、数字和连字符。
- `SKILL.md` 的 description 描述能力及适用场景；正文保留关键工作流与边界。
- 仅在实际需要时添加参考文档或脚本。重复、可确定执行的操作可抽成脚本；开放式判断保留为指导。
- 新建 skill 保持通常的自动发现方式，不因涉及执行权限而擅自改成仅显式调用。
- 校验文件格式、引用和参数化效果。新增脚本需运行验证；没有实际运行的检查不得标为通过。

挑选来自真实记录的代表性任务走查：正常输入是否得到预期产出，信息不足是否能正确处理，是否会扩大操作范围。高成本或外部写入步骤仅检查方案，除非另获执行授权。

若当前技能集合存在 `skill-manager`，按其既有分类映射登记新 skill，使下次发布时生成正确的 README 目录；只调整本次相关条目。联网发布、安装到其他目录或覆盖现有技能，以用户请求为准。

## 交付

说明分析了哪些记录、发现了哪些模式、哪些被选中或排除及原因。创建完成时给出 skill 文件链接、一个可直接使用的调用示例、验证结果和仍待真实使用验证的部分。

证据追踪只需保留必要的来源定位和摘要。用户未要求落盘时，候选报告留在对话中，不另建包含私人历史的档案。
