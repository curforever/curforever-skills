# Read Coach 设计说明

**日期：** 2026-07-26

**状态：** 已完成需求共创，待审阅
**目标位置：** `skills/learning/read-coach/`

## 1. 问题与目标

AI 时代的文章、教程、报告和 Markdown 文档产出速度很快，但读者常常没有足够时间或耐心读完。`read-coach` 要解决的不是“替用户摘要一篇文章”，而是帮助用户在有限时间内完成三件事：

1. 快速判断一篇材料是否值得投入时间；
2. 通过以问题和小测为主的互动，理解、推理并在适合时应用核心内容；
3. 留下可复习的学习记录，而不改动原文。

第一版以技术学习材料为设计基准，同时适用于观点长文、行业报告和其他泛知识内容。

## 2. 用户与输入

### 目标用户

- 想快速判断文章、教程、项目文档或 Markdown 是否值得读的人；
- 希望由对话引导完成学习，而不只是拿到摘要的人；
- 主要使用中文学习，但也会阅读英文或中英混合材料的人。

### 输入方式

支持两种输入：

- 提供本地文本文件路径；
- 直接在对话中粘贴正文。

本地文件优先支持 Markdown 与纯文本。英文或中英混合材料保留关键术语原文，评估、解释与反馈默认使用中文；用户可以临时指定其他讲解语言。

## 3. 用户体验与数据流

```text
文章路径或粘贴正文
  -> 文章结构识别与类型判断
  -> 30 秒阅读结论 + 可展开的质量评分
  -> 用户选择速览或互动学习
  -> 知识地图
  -> 单问题/短阅读任务循环
  -> 自适应追问、解释或回链原文
  -> 应用检验或立场辨析
  -> 最终掌握总结
  -> 同一份学习报告更新
```

评估完成后，默认先显示 30 秒结论：是否值得读、建议投入的阅读深度、3–5 个关键收获，以及主要风险或不足。用户可以选择速览、重点学习或深度学习。

进入互动学习前，固定显示新手提示：

> 你可以随时说：`速览`、`跳到第 N 点`、`结束并生成总结`。

每完成一个核心知识点，必要时以轻量提示提醒用户可调整节奏。互动默认每轮只处理一个问题或一个短阅读任务；以关键问题和小测为主，在用户回答不完整时回链至相应小节精读。用户完成时需要用自己的话总结；skill 再补足遗漏、边界和下一步。

## 4. 质量评分

每一维为 0–10 分，并且必须给出简短、可定位的依据和置信说明。分数是 AI 辅助判断，不是客观真值或事实核验结论。

| 维度 | 判断重点 |
| --- | --- |
| 可读性 | 结构、清晰度、术语负担、逻辑连贯性 |
| 可学习性 | 前置知识、示例、循序渐进程度、可练习性 |
| 准确与可信度 | 论据、来源、边界条件、过时或夸大风险 |
| 信息密度 | 有效信息与重复、空泛内容的比例 |
| 可应用性 | 能否转化为行动、决策或小练习 |

文章类型会影响评分解释和学习策略。例如，技术教程更重视前置知识、步骤可复现性和示例；观点文章更重视论据、逻辑与反例；报告更重视来源、方法和结论边界。

## 5. 学习模式与完成标准

学习过程按文章内容自动选择并组合三层完成证据：

1. 用户能用自己的话说明核心观点；
2. 用户能回答关键问题，并说明概念之间的关系或因果；
3. 用户能在真实场景、小练习或迁移判断中使用内容。

对于适合实践的材料，提供贴近日常、工作或技术实践的小场景；对于不适合实践的材料，改用立场辨析、反例检验或迁移判断。

## 6. 产物与文件规则

若输入来自本地文件且目录可写，生成一份与原文同目录的 Markdown 报告：

```text
原文.md
原文.read-coach.md
```

报告包含以下固定标题：

1. 30 秒结论；
2. 质量评分与依据；
3. 核心知识地图；
4. 互动学习记录；
5. 应用练习与答案要点；
6. 最终掌握总结与下一步。

原文绝不修改。粘贴正文时，skill 先询问保存目录与基础文件名；目录无写入权限时，保留完整对话输出，并明确说明报告未落盘。若报告已存在，默认询问用户选择覆盖、续写，或新建带时间戳的版本。

## 7. 技术设计

### 组件

| 组件 | 职责 |
| --- | --- |
| `SKILL.md` | 识别任务、控制交互流程、进行语义评分、讲解、提问与反馈 |
| `scripts/read_coach.py` | 检查与读取文本、提取标题/段落/代码块结构、创建或更新报告 |
| `references/rubric.md` | 评分量表及不同文章类型的判断准则 |
| `references/report-template.md` | 报告标题和记录格式模板 |
| `tests/` | 脚本与报告结构的自动验证 |

脚本只使用 Python 标准库，不调用外部 API、不保存跨会话档案，并且不承担定性学习判断；定性判断由 skill 完成。这样可以保持安装简单、行为可审阅且对外部环境依赖最少。

### 容错

- 非文本文件、空文件或无法读取：说明原因，并建议粘贴正文；
- 原文目录无写入权限：继续对话式学习，但不生成文件；
- 内容过长：先给结构化速评与阅读路线，让用户选择章节或分段学习；
- 已存在报告：请求用户选择覆盖、续写或带时间戳的新版本；
- 文章缺少标题或结构：退化为按段落和主题组织，不因格式不规范中断。

## 8. 仓库与发布结构

仓库根目录将作为个人 skills 集合的统一入口。第一版目录如下：

```text
4_Skills/
  README.md
  LICENSE
  .gitignore
  skills/
    learning/
      read-coach/
        SKILL.md
        README.md
        scripts/
        references/
        tests/
  docs/
    designs/
```

该单仓库按领域容纳多个独立 skill。每个 skill 自包含、可通过其子目录安装；仅在确实被多个 skill 使用时才在根目录添加 `shared/`。真实文章与生成的学习报告不进入此仓库。

默认建议采用 MIT License。未来只有当某个 skill 具有独立用户群、独立发布节奏、复杂运行依赖、不同许可证或独立维护需要时，才拆分为单独仓库。

## 9. 非目标

第一版不包含：

- 跨会话学习进度、知识库或复习提醒；
- 联网事实核验或文章真实性认证；
- 向第三方服务发送文章内容；
- 网页图形界面；
- 自动修改原文。

## 10. 验收与测试

使用匿名测试材料覆盖：结构完整的技术教程、结构松散的观点文、中英混合材料、空文件、不可写目录及已有报告场景。自动测试至少验证：

- 原文没有被改动；
- 报告文件命名正确；
- 六个固定章节完整；
- 互动记录可以正确追加；
- 错误条件给出可理解的反馈。

人工验收还应确认：评分依据能指向原文、问题推进不一次性倾倒内容、新手能看到节奏控制提示，并能在任意阶段安全结束并获得完整总结。
